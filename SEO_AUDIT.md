# Технический SEO-аудит сайта Прохук

Дата: 2026-10-09. Домен: `https://прохук.рф`
(`https://xn--j1ahceql.xn--p1ai`). Регион: Саратов, Россия.
Стек (определён по исходному коду): **Nuxt 4.5 (Vue 3.5, SSR/Nitro)**,
Node 24, каталог из МойСклад (снимок с юридическим фильтром), Playwright
e2e + node:test unit. Сайт продаёт ассортимент регулируемой продукции
18+ ⇒ все SEO-решения прошли правовую классификацию
(SEO_COMPLIANCE_AUDIT.md).

## 1. Резюме

**Стартовое состояние**: сайт полностью закрыт от индексации
(`robots.txt: Disallow: /` + глобальный meta `noindex, nofollow`),
аналитика отсутствует. Публикация не включалась до решения владельца
(модель зафиксирована в docs/COMPLIANCE.md).

**Ключевые проблемы (в порядке критичности)**:

| # | Проблема | Критичность | Влияние на индексацию |
| --- | --- | --- | --- |
| 1 | Сайт закрыт целиком; информационные страницы не индексируются | Критично | сайт отсутствует в выдаче |
| 2 | Мягкие 404: `/catalog/*`, `/product/*` отвечали **200** без подтверждения 18+ | Критично | обход мусорных URL, риск «URL без описания», искажение статистики обхода |
| 3 | Нет sitemap.xml | Высокая | нет карты для ускорения индексации 8 целевых страниц |
| 4 | Нет canonical/og:url — риск дублей с query-параметрами | Высокая | размывание сигналов |
| 5 | Нет аналитики (Метрика) | Высокая | нет данных о посещениях |
| 6 | Возрастной гейт скрывал контент ВСЕХ страниц в SSR — включая информационные | Высокая | для робота даже «/» была пустой |
| 7 | robots.txt не отражал архитектуру (был `Disallow: /`) | Средняя | — |
| 8 | Нет структурированных данных | Средняя | потеря расширенных сниппетов (организация, точки продаж) |
| 9 | Политика ПД заявляла «аналитики нет» — блокировала подключение Метрики | Критично (право) | — |

**Быстрые победы, реализованные сразу**: sitemap, файл подтверждения
Вебмастера, granular robots.txt, canonical, per-page robots, JSON-LD,
Метрика, фикс мягких 404.

## 2. Технический аудит по областям

### 2.1. Доступность и HTTP

- Прод-домен отвечает (CI уже прогоняет `curl https://прохук.рф` после
  каждого деплоя), HTTPS + HSTS (1 год, includeSubDomains).
- Заголовки безопасности: CSP, X-Frame-Options: DENY, nosniff,
  Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy —
  все на месте (`nitro.routeRules`); CSP дополнена `mc.yandex.ru`
  (script/img/connect) без ослабления остальных директив.
- **Мягкие 404** — исправлено: `definePageMeta.validate` в
  `app/pages/catalog/[category].vue` и `app/pages/product/[slug].vue`
  проверяет существование категории/товара на этапе middleware — до
  рендера и независимо от age cookie. До фикса механизм был такой:
  layout не рендерит слот без подтверждения 18+ → setup страницы не
  выполняется → `createError(404)` не срабатывает → 200 с заглушкой.
  Проверено: `/catalog/nonexistent`, `/product/nonexistent`,
  `/nonexistent` → 404 (тест `tests/seo.spec.ts`).
- `/about/` (трейлинг-слэш) → 404, не дубль (маршруты Nuxt строгие);
  canonical всегда без слэша и без query.

### 2.2. Кириллический домен (IDN)

- punycode-форма: `прохук.рф` ⇔ `xn--j1ahceql.xn--p1ai` (совпадает с
  проверкой CI; тест «punycode-домен стабилен»).
- Все машинные представления (canonical, sitemap `<loc>`, robots.txt
  `Sitemap:`) используют одну punycode-форму через
  `canonicalSiteUrl()` (WHATWG URL сериализует хост в ASCII) — дублей
  между кириллицей и punycode нет; кириллическое написание остаётся
  пользовательским.
- http→https и www-редиректы производит nginx VPS (вне репозитория);
  рекомендация в SEO_ROADMAP.md §30 дней — проверить 301
  `www.xn--j1ahceql.xn--p1ai` → голый домен.

### 2.3. Индексация: что открыто, что закрыто

Индексируются (см. классификацию — SEO_COMPLIANCE_AUDIT.md §2):
`/`, `/about`, `/stores`, `/contacts`, `/information`, `/partners`,
`/privacy`, `/personal-data` — **8 страниц**, `index, follow` +
canonical + og:url + JSON-LD.

Закрыто: `/catalog*`, `/product/*` (витрина регулируемой продукции —
noindex до юридического решения), `/search`, `/reserve`, `/login`,
`/register`, `/account`, `/design-system`, `/api/*` (robots Disallow +
meta noindex). Каталогозависимые секции главной (категории, «Недавно
обновлено», бренды) не рендерятся в SSR без подтверждения 18+ —
юридический инвариант сохранён (тесты `tests/legal.spec.ts`,
`tests/seo.spec.ts`).

### 2.4. Robots.txt

Было: `Disallow: /` (публикация не включалась). Стало — гранулярно:
закрыты приватные/служебные маршруты и `/product/` (≈4 тыс. URL,
контент скрыт гейтом — чистая экономия обхода); CSS/JS (`/_nuxt/`) не
закрыты; добавлен `Sitemap:`. robots.txt не используется как механизм
защиты ПД (приватность обеспечивают noindex и серверная авторизация).

### 2.5. Sitemap.xml

`server/routes/sitemap.xml.ts`: 8 URL, абсолютные HTTPS punycode,
`Content-Type: application/xml; charset=utf-8`, `Cache-Control: public,
max-age=3600`, `X-Robots-Tag: noindex`. Товарные карточки не включались
автоматически — после правовой проверки (вывод: не включать до решения
юриста). Фиктивный `lastmod` не проставляется (протокол запрещает
недостоверные даты). Защита от дублей URL внутри карты — в коде и тесте.

### 2.6. Метаданные

- `usePageSeo` переписан: per-page robots (дефолт `noindex, follow`,
  индексируемые — `index, follow`), canonical, og:url/og:locale,
  BreadcrumbList JSON-LD для страниц с крошками.
- Глобальный дефолт `nuxt.config.app.head`: `noindex, nofollow` —
  страховка для будущих страниц без явного robots (переопределяется
  страницей; единственность meta robots — тестом).
- Заголовки индексируемых страниц — фактологические, без рекламной
  семантики (пример: «Сеть магазинов в Саратове и Москве — Прохук»).
- Файл подтверждения Вебмастера: `public/yandex_637e4d2139cdf333.html`
  (YANDEX_WEBMASTER_SETUP.md).

### 2.7. Рендеринг и JS

SSR отдаёт полный HTML информационных страниц (заголовки, текст, адреса,
JSON-LD) — робот получает контент без выполнения JS. Возрастной гейт —
клиентский диалог; для робота каталогные маршруты показывают
информационную заглушку + noindex (не «мягкий бан»).

### 2.8. Структурированные данные

`Organization` (все страницы), `WebSite` (главная), `BreadcrumbList`
(about/stores/contacts/partners/информация/политики), `Store` ×30
(/stores: адрес, город, телефон, geo при наличии, часы при однозначном
разборе). Запрещённые типы (Product/Offer/AggregateRating) отсутствуют —
тест. Валидация: JSON парсится в тестах; рекомендована проверка в
Яндекс Вебмастере («Проверка микроразметки») после выката.

### 2.9. Аналитика

Метрика 113582832 подключена централизованно (плагин), SPA-хиты без
двойного учёта, 9 разрешённых событий с allowlist параметров, noscript
-пиксель, CSP дополнена (YANDEX_METRIKA_SETUP.md). Ecommerce —
`dataLayer` не заполняется, purchase-события не создаются
(недостоверно и стимулирующе для регулируемой продукции).

### 2.10. Каталог и МойСклад (интеграционный аудит)

- Модель данных: снимок `.cache/moysklad/catalog.json` → юридический
  фильтр (`shared/legal/classification.ts`) → `server/api/products*`.
  Скрытые классы (BANNED/PENDING) не публикуются — тест
  (`tests/legal.spec.ts`).
- URL товаров: `/product/{slug}` — slug из атрибута «Название для
  сайта» (массовое переименование 6319/6319 позиций выполнено ранее);
  дубли slug исключаются маппером, несуществующие slug → 404 (validate).
- Категории: `/catalog/{slug}`, иерархия родитель→потомок; несуществующие
  → 404 (validate). Пустые корневые категории не публикуются
  (юридический фильтр).
- Изображения: прокси `/api/products/{id}/images/{index}` — токен
  МойСклад не покидает сервер; URL стабильные, кешируемые.
- Остатки/цены: синхронизация `catalog:sync`, количество публикуется
  только как enum наличия (точные остатки наружу не отдаются);
  «Скоро в наличии» вместо «Нет в наличии».
- Рекомендации по устойчивости URL при изменениях данных — в
  SEO_ROADMAP.md §60 дней (история slug/301 с карты старых slug).

### 2.11. Локальная информация

`/contacts`: телефон, почта, режим работы, соцсети, карта всех точек
(Яндекс.Карты JS API 2.1 — российский сервис, мандат владельца);
адреса доступны и без загрузки карты (текстовый список + `<noscript>`
-заглушка), `/stores` — полный список 30 точек с адресами и часами.
Разметка семантическая (address в JSON-LD, h1/h2, dl-списки).
Карта лениво не грузится — замечание в производительность (§2.12).

### 2.12. Производительность

Лабораторный замер (мобильная эмуляция: Slow 4G 1,6 Мбит/с, RTT 150 мс,
CPU ×4, viewport 390×844; медиана из 3 прогонов; скрипт
`scripts/seo-perf-measure.mjs`) — числа «до/после» в
SEO_IMPLEMENTATION_REPORT.md §Performance. Выполнено в этой итерации:
preload LCP-изображения главной (`/brand/mark-large.webp`,
fetchpriority=high), фоновая загрузка копирайт-изображений (loading=lazy
уже стоял в футере). Открытые возможности (роадмап): ленивая
инициализация карты по видимости, `Clean-param`, аватарки WebP в
прокси-изображениях (уже sharp), HTTP/2-кеширование статики на nginx.

### 2.13. Мобильная версия

Отзывчивая вёрстка (один домен, без m.), адаптив проверен e2e-тестом
«main pages fit mobile and desktop widths» (375/768/1440). Tap-targets,
viewport, шрифты — из дизайн-системы; отдельных проблем не найдено.

## 3. Ошибки, исправленные в этой итерации

1. Глобальное noindex на информационных страницах → per-page index.
2. Мягкие 404 каталога/товаров → `validate()` → честный 404.
3. Отсутствие sitemap.xml → динамическая карта (8 URL).
4. Отсутствие canonical → абсолютный punycode-canonical + og:url.
5. Отсутствие аналитики → Метрика 113582832 (SPA-safe).
6. Политика ПД не соответствовала будущей аналитике → переписана
   (cookie-перечень дополнен `prohook-session`, добавлен п. 3.6).
7. Нет структурированных данных → Organization/WebSite/Store/Breadcrumb.
8. Возрастной гейт скрывал и информационные страницы → они открыты,
   гейт для витрины сохранён (инвариант закрыт тестами).
