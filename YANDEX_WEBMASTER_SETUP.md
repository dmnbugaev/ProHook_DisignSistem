# Яндекс Вебмастер — подключение сайта Прохук

Дата: 2026-10-09. Домен: **https://прохук.рф**
(punycode: `https://xn--j1ahceql.xn--p1ai`).

## 1. Способ подтверждения прав

Выбран официальный способ **«HTML-файл»** — не требует DNS/метатегов и
работает поверх любой конфигурации reverse-proxy, отдающей статику
Nuxt/Nitro.

| Параметр | Значение |
| --- | --- |
| Имя файла | `yandex_637e4d2139cdf333.html` |
| Расположение в репозитории | `public/yandex_637e4d2139cdf333.html` |
| URL проверки | `https://прохук.рф/yandex_637e4d2139cdf333.html` |
| Код подтверждения | `637e4d2139cdf333` |

Содержимое файла — строгое, по требованиям Яндекс Вебмастера:

```html
<html>
    <head>
        <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    </head>
    <body>Verification: 637e4d2139cdf333</body>
</html>
```

## 2. Как файл попадает на прод

`public/` в Nuxt копируется в корень дистрибутива при сборке
(`.output/public/`). Nitro отдаёт файлы из `public/` до обращения к
SSR-роутингу, поэтому:

- файл **не** попадает под SPA-fallback и не редиректится на главную;
- отдаётся без авторизации, с `Content-Type: text/html`.

Деплой на VPS (5.63.158.22) выполняется существующим скриптом
`prohook-deploy` после зелёного CI на `main` (`.github/workflows/ci.yml`).
После мержа этой ветки файл появится на проду автоматически.

## 3. Результат локальной HTTP-проверки

Проверено на production-сборке (`node .output/server/index.mjs`) и на
dev-сервере, зафиксировано автотестом
`tests/seo.spec.ts` → «файл подтверждения Яндекс Вебмастера»:

- `GET /yandex_637e4d2139cdf333.html` → **HTTP 200**;
- редиректов нет (проверяется отсутствие смены URL);
- тело содержит `<body>Verification: 637e4d2139cdf333</body>`;
- кодировка UTF-8 заявлена и в заголовке файла.

## 4. Действия, требующие доступа владельца

Код подтверждения выдан Яндексом на аккаунт владельца — завершить
добавление сайта нужно в интерфейсе:

1. Открыть https://webmaster.yandex.ru → «Добавить сайт» → ввести
   `https://прохук.рф`.
2. Способ подтверждения — «HTML-файл»; Яндекс распознает файл после
   деплоя (см. §2) — нажать «Проверить».
3. После подтверждения в разделе «Индексирование → Файлы Sitemap»
   добавить `https://прохук.рф/sitemap.xml` (карта отдаётся с
   `Content-Type: application/xml; charset=utf-8`, 8 URL).
4. В «Проверка ответа сайта» убедиться, что главная отвечает 200, а
   несуществующие страницы — 404 (исправлено в этой итерации; см.
   SEO_AUDIT.md §«Мягкие 404»).
5. Регион сайта: указать **Саратов, Россия** («Информация о сайте →
   Региональность») — домен обслуживает сеть магазинов Саратова и Москвы,
   основной регион — Саратов.
6. Через 1–2 недели посмотреть «Обход» и «Индексирование» на предмет
   страниц вида `/catalog?…` — при росте обхода фильтрованных URL
   добавить `Clean-param` (roadmap, SEO_ROADMAP.md).

## 5. Замечания по инфраструктуре

- Nginx на VPS проксирует запросы к Nitro; файлы из `public/` отдаёт
  Nitro, отдельной nginx-локации не требуется. Если на проду файл вдруг
  начнёт редиректить (например, из-за http→https-правил), проверять
  нужно именно nginx-редиректы верхнего уровня — в приложении редиректа
  нет (подтверждено тестом).
- HTTPS обязателен: HSTS уже включён (`max-age=31536000; includeSubDomains`).
