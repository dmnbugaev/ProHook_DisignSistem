# Compliance — юридико-технический аудит и меры соответствия

Нормативный срез: **07.10.2026** (обновлён при внедрении запросов на резерв).
Документ отражает состояние кода на дату аудита и решения владельца,
зафиксированные при согласовании (см. историю).

> Документ не является юридическим заключением и не заменяет консультацию
> юриста. Пункты с пометкой **LEGAL REVIEW REQUIRED** требуют решения
> владельца/юриста до публикации сайта.

## 1. Целевая юридическая модель

«Справочно-информационный сайт-каталог + список выбранных товаров с запросом
на резерв для самовывоза + розничная продажа исключительно в физическом
магазине после проверки возраста покупателя».

Реализовано и подтверждено тестами:

- оплаты, доставки, checkout, платёжных ссылок и избранного **нет** ни в UI,
  ни в API (`tests/legal.spec.ts` инварианты, включая страницу `/reserve`);
- список выбранных товаров (`/reserve`) — это **запрос на резерв**:
  формирование списка → выбор физического магазина → отправка запроса →
  обработка сотрудником → визит покупателя → проверка возраста → продажа и
  оплата только в магазине. Терминология проекта: «список выбранных товаров»,
  «запрос на резерв», «самовывоз»; сущность в коде — `ReservationRequest`,
  не `Order`; статусы онлайн-оплаты (`PAID` и аналоги) отсутствуют по
  построению;
- единый CTA каталога — переход в карточку товара; кнопки «Купить/Заказать/
  Оформить/Оплатить/Доставка» отсутствуют, добавление в список называется
  «В список»;
- в `/information` указано: ознакомление с каталогом не является заказом и не
  порождает обязательств продавца (ПП РФ от 30.05.2026 № 657, п. 19 —
  предварительное согласование не признаётся дистанционной продажей); там же
  описан режим «запрос на резерв и самовывоз»;
- сайт не принимает оплату и не доставляет товары: запрос не является
  офертой/заказом, договор розничной купли-продажи заключается только в
  магазине; цены в списке не фиксируются (priceSnapshot намеренно отсутствует);
- продажа, идентификация возраста, оплата и выдача чека — только в магазине.

## 4. Региональные ограничения

`shared/legal/regional-restrictions.ts`. Активируются автоматически по дате:
для магазинов региона скрываются офферы запрещённых классов, товары без
оставшихся офферов исключаются из выдачи (влияние на API и карточки).

- Саратовская область: запрет розничной продажи ЭСДН и жидкостей
  с **01.03.2027** по 01.03.2032 (закон области, 2026). В конфигурации сайта
  региону соответствует `cityId=saratov`.
- Москва: на дату среза ограничений нет — отслеживать (регионы вправе вводить
  запреты до 01.03.2032; к октябрю 2026 воспользовались 5 субъектов).

Список нужно актуализировать при новых региональных законах.

## 5. Data Flow Map

```
Посетитель

   prohook-age-confirmed, 1 год, только локально; контент каталога не
   рендерится в SSR-HTML до подтверждения; юридические страницы открыты)
 → каталог: МойСклад (api.moysklad.ru, РФ) → сервер сайта → снимок
   .cache/moysklad/catalog.json (0600) с применённой юридической политикой
   → /api/products (только опубликованные классы) → браузер
 → изображения: прокси /api/products/:id/images/:index (токен не покидает сервер)
 → выбор магазина: cookie prohook-store (30 дней, строго необходимая)
 → форма /partners: ФИО, телефон, город/регион, компания, текст предложения
   + 2 согласия → POST /api/partnership (no-store, лимит 5/15мин по IP —
   IP только в памяти процесса ≤15 мин; honeypot; 8 КБ; без логирования ПД)
   → api.telegram.org (ТРАНСГРАНИЧНАЯ передача, раскрыта в политике и
     отдельном согласии; хранение — чат Telegram; локальной копии нет)
 → список выбранных товаров: cookie prohook-selection (30 дней, строго
   необходимая, только productId+количество; сервер данные клиента не
   доверяет и всё перепроверяет)
 → форма /reserve: имя, телефон, комментарий, магазин, перечень товаров
   + 2 согласия + SmartCaptcha → POST /api/reservations (no-store, лимит
   5/15мин по IP; honeypot; 8 КБ; Idempotency-Key от дублей; серверная
   проверка капчи smartcaptcha.yandexcloud.net; проверка магазина/товаров/
   остатков по снимку МойСклад; авторизованные несовершеннолетние аккаунты
   получают 403) → ReservationRequest в .data/reservations (0600, 30 дней)
   → уведомление боту @prohook_bunker_site_bot → api.telegram.org
   (ТЕЛЕГРАМ — НЕ хранилище: сбой доставки запрос не теряет, повтор
   доставки не создаёт дублей)
Аналитика, пиксели, профилирование: отсутствуют.
БД как сервис: отсутствует; ПД форм хранятся в файловых хранилищах
сервера (.data, 0600, вне Git) ограниченный срок.
```

## 7. Реализованные технические меры

- **Classification layer** (`shared/legal/`): единая точка юридической
  политики; фильтрация применяется в маппере и повторно при загрузке снимка
  (идемпотентно) — старые кэши/фикстуры тоже фильтруются.
- **Региональные запреты** по дате с unit-тестами на будущее/прошлое.
- **Удалены механизмы стимулирования**: бейджи «Новинка»/«Выбор коллекции»,
  `isPopular`/`isNew`, зачёркнутая `oldPrice` (типы, маппер, демо-данные, UI).
  Сортировка «Недавно обновлены» (по дате) сохранена как нейтральная.
- **Age gate**: cookie-персистенция; SSR не отдаёт контент каталога до
  подтверждения; noscript-заглушка; юр. страницы (`/privacy`,
  `/personal-data`, `/information`, `/contacts`) доступны без гейта.
- **Юридические страницы**: `/privacy`, `/personal-data`, обновлён
  `/information` (продавец, лицензии, региональные ограничения), реквизиты в
  футере, пометка об Instagram/Meta.
- **Согласия**: два раздельных обязательных чекбокса, оба пустые по умолчанию,
  со ссылками на текст согласия и политику; сервер валидирует оба.
- **МРЦ**: `shared/legal/min-prices.ts` + предупреждения в `catalog:sync`
  (пороги задаёт владелец после сверки; автоизменения цен нет).
- **Лицензии 186-ФЗ**: `server/data/store-licenses.ts` (пусто до получения);
  отображение в `/stores` и `/information` только при заполненности.
- **Security**: CSP, X-Frame-Options DENY, nosniff, Referrer-Policy,
  Permissions-Policy, HSTS (`nuxt.config.ts`); robots.txt `Disallow: /`.
- **Тесты-инварианты** (`tests/legal.spec.ts`, `tests/legal-policy.test.mjs`):
  запрещённые категории не публикуются; SSR без утечки контента; согласия не
  pre-checked; на страницах каталога и странице `/reserve` нет лексики
  покупки/доставки/скидок; заголовки безопасности присутствуют; региональный
  фильтр по дате.
- **Запрос на резерв** (`server/api/reservations.post.ts`): сервер не доверяет
  клиенту — магазин, товары, остатки и количество перепроверяются по снимку
  МойСклад (включая региональные запреты и точные остатки `stockDetail`,
  которые наружу не публикуются); цена не принимается и не фиксируется
  (priceSnapshot отсутствует намеренно); идемпотентность по
  `Idempotency-Key`; rate limit 5/15 мин; SmartCaptcha проверяется только на
  сервере; Telegram-allowlist в env (`TELEGRAM_RESERVATION_CHAT_IDS`), клиент
  не передаёт ни chat_id, ни текст сообщения; сообщение — plain text без
  parse_mode; ПД запроса — имя, телефон, комментарий, перечень товаров
  (минимально необходимые сотруднику магазина); хранение 30 дней, статусная
  модель без онлайн-оплаты (`PENDING/CONFIRMED/READY/REJECTED/EXPIRED/
  COMPLETED/CANCELLED`).

## 8. Что невозможно обеспечить кодом (обязанности владельца)

1. **Уведомление Роскомнадзора** об обработке ПД (152-ФЗ ст. 22) с указанием
   трансграничной передачи в Telegram; назначить ответственного за
   организацию обработки ПД (ст. 22.1 — при необходимости).
2. **Фактическая проверка возраста** в магазинах при продаже (гейт сайтом не
   является проверкой возраста); паспортный контроль продавцами.
3. **Лицензии 186-ФЗ**: подать заявления (регионы выдают с 01.10.2026);
   **до 01.03.2027 торговля без лицензии запрещена**. Получив реквизиты —
   внести в `server/data/store-licenses.ts` (появятся на сайте).
4. **МРЦ**: сверить пороги с действующей редакцией постановления и внести в
   `shared/legal/min-prices.ts`; проверить фактические цены МойСклад.
5. **Законность оборота скрываемых категорий**: сигареты, НБС, ароматизаторы —
   юридическая оценка и решение (см. §9); снять блокировку может только
   владелец изменением классификации. По паучам — подтвердить у поставщиков
   отсутствие табака в составе (снюс запрещён к обороту).
6. **Хостинг при публикации**: сервер и снимок каталога — на хостинге в РФ
   (локализация каталожных данных и cookie-данных не строга, но рекомендуема);
   HTTPS обязателен.
7. **Процедура отзыва согласия**: назначить сотрудника, удаляющего заявки из
   чата Telegram по обращению (телефон/e-mail указаны в политике); для
   запросов на резерв — также удалять запись из `.data/reservations`
   (вручную по номеру R-… или скриптом).
8. **Ключи интеграций резервов**: `TELEGRAM_BOT_TOKEN` (бот
   @prohook_bunker_site_bot), `TELEGRAM_RESERVATION_CHAT_IDS`,
   `SMARTCAPTCHA_SERVER_KEY` + `NUXT_PUBLIC_SMARTCAPTCHA_CLIENT_KEY` —
   задать в server-side окружении до публикации; без серверного ключа
   капчи форма защищена только rate limit и honeypot.
9. **Регламент обработки запросов на резерв**: сотрудник магазина получает
   уведомление, связывается с покупателем при необходимости и подтверждает
   наличие; запрос не резервирует товар в МойСклад автоматически — решение о
   механике резерва в учётной системе за владельцем (см. §9).
10. **Актуальность контактов**: телефон/email взяты из открытого сообщества ВК;
   подтвердить владельцем.

## 9. Открытые вопросы (LEGAL REVIEW REQUIRED)

1. **Квалификация «резерв + самовывоз»**: 15-ФЗ (ст. 19) запрещает
   дистанционную продажу табачной и никотинсодержащей продукции. Сайт
   реализован максимально консервативно (запрос, не заказ; без оплаты,
   доставки и фиксации цены; продажа и проверка возраста — только в
   магазине), что следует практике рынка и ПП РФ № 657 п. 19 о
   предварительном согласовании. Правоприменение по схемам
   «бронирование онлайн» неоднородно: рекомендуется письменное подтверждение
   юристом выбранной модели и формулировок до публикации. Рисковые факторы
   для оценки: демонстрация цен и наличия (уже существующий сайт-каталог),
   использование слова «резерв» (в интерфейсе всюду «запрос на резерв»).
2. **Резерв в МойСклад**: сущность «Заказ покупателя» не создаётся — не
   запускать без юридической оценки; запрос хранится во внутренней БД,
   МойСклад используется только как источник данных.
3. **Вкусовая НСП**: в актуальном прайсе ~1 600+ наименований со вкусами при
   запрете оборота НСП с нембачными вкусовыми добавками с 01.03.2025 (365-ФЗ).
   Распространяется ли на паучи — проверить у юриста. Требуется ответ
   владельца: фактический ассортимент и законность оборота; при риске —
   рассмотреть скрытие «вкусовых» SKU.
4. **«Ароматизаторы»/«ПДНКИ» (1 468 SKU)**: пищевые концентраты или компоненты
   НСП? От ответа зависит класс (UNREGULATED vs REGULATED_NICOTINE).
5. **Паучи («Жевательный табак», 309 SKU)** — владелец подтвердил: безтабачные
   никотиновые паучи, публикуются как REGULATED_POUCH. Осталось проверить:
   (а) отсутствие табака в составе каждой позиции (снюс запрещён к обороту);
   (б) вкусовые добавки после 01.03.2025; (в) охват саратовского запрета
   2027 г. (закон об ЭСДН и жидкостях — паучи предположительно не входят,
   сверить формулировку); (г) применимость МРЦ к паучам.
6. **Программа лояльности** (упомянута в VK): на сайт не переносится;
   подтвердить, что скидки/бонусы на НСП не будут запускаться (запрещено).
7. **Жидкости 0 мг / устройства без никотина**: маркировка распространяется с
   15.12.2022; классификация в каталоге по категориям не различает
   содержание — уточнить у владельца при необходимости.
8. **IP в rate-limiter** — оценка Роскомнадзора о квалификации IP как ПД
   учтена (включён в политику, срок ≤15 мин, память процесса).

## 10. Остаточные риски

- **Telegram-канал ПД**: трансграничная передача с полным содержимым заявки
  (решение владельца — «оставить как есть + документировать»). Уровень
  защиты зависит от настроек приватности чата команды; рассмотреть миграцию
  на «ID-only + хранилище в РФ» при появлении БД.
- **CSP `'unsafe-inline'` для script-src**: обусловлена inline-скриптом
  состояния Nuxt; интерполяция Vue экранируется, пользовательский HTML не
  рендерится, поэтому XSS-поверхность минимальна, но строгость CSP снижена.
- **Мягкие 404**: для посетителя без подтверждения возраста несуществующие
  маршруты отвечают 200 с гейтом (контент ошибок не отдаётся); после
  подтверждения — корректные 404. На индексацию не влияет (noindex).
- **МойСклад как источник истинности**: цены/остатки публикуются как есть;
  незаконная цена в учётной системе отразится на сайте (МРЦ-валидатор только
  предупреждает при синхронизации).
- **Региональное законодательство** меняется — требуется мониторинг (§4).

## 11. Чек-лист публикации

1. Закрыть вопросы §9; заполнить МРЦ-пороги; получить лицензии (до 01.03.2027).
2. Уведомление РКН подано; ответственный назначен.
3. Хостинг РФ + HTTPS; `NUXT_MOYSKLAD_TOKEN`, `NUXT_TELEGRAM_*` в окружении.
4. `robots.txt`: убрать `Disallow` и мета `noindex` **только после решения о
   индексации**; товарные фиды/merchant-разметка/Offer-JSON-LD для
   регулируемых категорий **не создаются** (риск квалификации как реклама).
5. Прогнать `npm run lint && npm run typecheck && npm run build &&
   npm run test:unit && npm test`.
