# Прохук — визуальная дизайн-система

Версия: 1.0 · Дата: 27 сентября 2026 года · Статус: реализованная интерактивная витрина на Nuxt 4.

Документ описывает согласованную дизайн-систему. Заказчик выбрал Nuxt-витрину, базовый комплект компонентов, Golos Text, чистый строгий характер и геометрическую анимацию при скролле. Товарный каталог, промосцены продукции, цены, остатки, МойСклад и карты магазинов в этот этап не входят.

## 1. Зафиксированные решения

- Название в обычном тексте — «Прохук». Написание внутри предоставленного логотипа сохраняется.
- Основа айдентики — предоставленный знак и начертание логотипа «ПРОХУК».
- Основной фон всех страниц — строго белый, #FFFFFF.
- Основной текст, контуры и пиктограммы — чёрные, #000000.
- Фирменный акцент — #FFFE00. Жёлтые интерактивные элементы получают чёрную рамку.
- Визуальное направление — чистая строгая композиция с крупной типографикой, свободным пространством и геометрическим акцентом.
- Десктопная и мобильная версии имеют одинаковую содержательную полноту.
- Прозрачная навигация на первом экране переходит в светлую стеклянную панель при прокрутке.

Все размеры ниже — предлагаемые дизайн-решения, а не извлечённые из официального брендбука требования.

## 3. Визуальный характер

Белая плоскость, выразительный чёрный знак, крупный гротеск и ограниченные жёлтые акценты. Узнаваемость строится на геометрии существующего знака, а не на наборе случайных «технологичных» украшений.

Брутализм выражается через уверенную типографику и заметные контуры. Технологичность — через точные выравнивания и ясные состояния элементов. Качество — через чистые исходники, свободное пространство и последовательность размеров.

Один выразительный композиционный приём на экран. Внутренние информационные страницы спокойнее первого экрана. Полностраничная тёмная тема, декоративный неон, дым, цветные градиенты и постоянные бегущие строки в базовую систему не входят.

## 4. Логотип и фирменная геометрия

- Использовать предоставленные оригиналы; для публикации предпочтителен утверждённый векторный исходник.
- Не растягивать знак, не менять форму его сторон и не обводить сам чёрный силуэт дополнительным контуром.
- Не собирать новый логотип из системного текста и отдельно поставленного символа.
- Охранное поле: предварительно не менее четверти высоты знака с каждой стороны. Заменить официальным значением, если появится брендбук.
- Отдельный знак в навигации: ориентировочно 32–40 px по высоте. Полный вертикальный lockup использовать там, где подпись остаётся читаемой, например в разделе об айдентике.
- На мобильном допустим компактный знак с доступным названием «Прохук» для скринридера.
- Ступенчатые края применяются в иллюстрациях и крупных декоративных плашках; поля ввода и кнопки сохраняют простую геометрию.
- Растровые артефакты по краям приложенных файлов не считать намеренной текстурой без подтверждения.

## 5. Цветовая палитра

| Токен | Значение | Назначение |
| --- | --- | --- |
| background | #FFFFFF | Основной фон каждой страницы, основной фон секций |
| ink | #000000 | Текст, логотип, активные контуры, иконки |
| accent | #FFFE00 | Активные переключатели, отдельные кнопки, небольшие графические акценты |
| surface-subtle | #F5F5F5 | Локальная подложка изображения или служебного блока |
| text-secondary | #595959 | Подписи и вторичная информация на белом |
| separator | #D9D9D9 | Некритичные декоративные разделители |

Ориентир для обычного экрана: 80–90% светлой поверхности; жёлтый занимает небольшую акцентную долю. Это композиционный ориентир, а не квота на каждый экран. Большие чёрные буквы и знак допустимы на белом фоне.

Жёлтые кнопки и плашки: чёрный текст и чёрная рамка 2 px. Для небольшой метки допустима рамка 1 px. Чёрный контур формирует границу жёлтого на белом. Белый текст на жёлтом и жёлтый текст на белом не использовать.

Служебные ошибки передаются текстом и пиктограммой, а не одним цветом. Тонкий светло-серый разделитель не заменяет видимую границу поля ввода. Основная страница, включая footer, остаётся белой.

## 6. Typography

Утверждён Golos Text: единое семейство для заголовков, навигации и основного текста. Начертание логотипа остаётся оригинальным. Локальные WOFF2 с кириллицей и латиницей подключены через @fontsource-variable/golos-text, font-display: swap. Лицензия SIL OFL 1.1 включена в public/fonts. Резервный вариант — Arial / системный sans-serif.

Крупные заголовки: трекинг от −0.03em до −0.01em после оптической проверки. Основной текст — без искусственного уплотнения. Прописные буквы допустимы в краткой композиционной надписи, но не во всех элементах интерфейса.

Длина строки основного текста — 55–75 знаков. Выравнивание по левому краю. Не растягивать абзацы по ширине. Высоту текстовых блоков не фиксировать: длинные слова, увеличение шрифта и переносы не должны обрезаться.

## 7. Spacing system

Базовый модуль — 4 px. Основная шкала: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128 px.

| Ситуация | Desktop | Mobile |
| --- | --- | --- |
| Иконка и текст | 8 px | 8 px |
| Заголовок и пояснение | 16 px | 12 px |
| Элементы одной группы | 16–24 px | 12–16 px |
| Внутренний отступ карточки | 24 px | 16 px |
| Между колонками | 24 px | 16 px |
| Заголовок секции и содержимое | 32–48 px | 24 px |
| Между крупными секциями | 96–128 px | 56–64 px |

Внешние отступы соседних секций задаются одним общим интервалом; не складывать автоматически два больших padding. Пустое пространство поддерживает иерархию, а не растягивает страницу без причины.

| Ширина окна | Колонки | Боковые поля | Gutter |

- Основной контейнер: максимум 1320 px, по центру, с указанными минимальными боковыми полями.
- Широкое декоративное полотно: максимум 1600 px; значимый текст остаётся в основном контейнере.
- Контейнер длинной статьи: максимум 720 px.
- Диалог: максимум 480 px; на телефоне ширина окна минус 32 px.
- На экранах шире 1600 px увеличиваются внешние поля, а не размер основного текста.
- Ширина 320 px поддерживается без горизонтальной прокрутки страницы.

Секции используют общие вертикальные оси. Внутри 12 колонок допустимы схемы 5 + 7, 6 + 6, 4 + 8. Декоративный объект может пересекать сетку, текст и элементы управления — нет.

## 9. Border radius, контуры и тени

| Объект | Радиус |
| --- | --- |
| Декоративные геометрические блоки | 0 px |
| Кнопки и поля ввода | 6 px |
| Информационные карточки | 8 px |
| Стеклянная панель навигации | 12 px |
| Диалоги и мобильная панель | 16 px |
| Круглая иконка или индикатор | 50%, только по функции |

Основной выразительный контур — 2 px чёрного. Контур нейтрального поля — 1 px чёрного. Толщина рамки при hover не меняется, чтобы избежать скачка размеров.

Карточки по умолчанию без тени. Лёгкая тень допустима у плавающей навигации и диалога для отделения от фона. Чёрная тень со смещением 3 px может использоваться у одной акцентной кнопки; не размножать её по всей странице.

## 10. Карточки и информационные блоки

Нейтральная карточка материала: изображение при наличии → заголовок → короткое пояснение → дата или тип материала, если это помогает пониманию. Внутренние отступы 24 / 16 px, радиус 8 px, белый фон. Изображения в одной группе имеют одинаковое соотношение сторон, по умолчанию 4:3.

Основной заголовок не обрезается до нечитаемого фрагмента. В ряд ставятся карточки одной роли. Не превращать каждый абзац и каждую контактную строку в отдельную плитку.

Если карточка ведёт к материалу, название получает ясное состояние ссылки. Вложенные кнопки не должны создавать конфликт с кликом по всей карточке. Важные сведения всегда видны, а не появляются только при наведении.

## 11. Кнопки и hover states

| Вариант | Обычное состояние | Hover | Pressed |
| --- | --- | --- | --- |
| Основная | #FFFE00, чёрный текст, рамка 2 px | Сохраняет цвет; тень или подъём до 1 px | Возвращается на базовую линию, тень уменьшается |
| Вторичная | Белая, чёрный текст, рамка 2 px | Жёлтая заливка | Чёрная заливка, белый текст |
| Текстовая ссылка | Чёрная, подчёркнута внутри абзаца | Более выраженное подчёркивание | Без изменения геометрии |
| Кнопка-иконка | Белая / прозрачная в зависимости от поверхности | Жёлтая подложка с чёрной границей | Небольшое изменение заливки |

Высота основной кнопки — 48 px, крупной — 56 px. Горизонтальные отступы — 24 px. Минимальная зона касания всех элементов — 44 × 44 px. Подписи описывают результат действия: «Читать материал», «Открыть меню», «Закрыть».

Focus: отдельное чёрное внешнее кольцо 2 px с белым зазором 3 px; оно не заменяется hover. Для тёмного локального элемента белый зазор сохраняет различимость. Disabled: спокойная серая поверхность и доступное пояснение причины, если она неочевидна.

Hover действует только на устройствах с точным указателем. На телефоне интерфейс не требует первого касания для раскрытия второго действия.

## 12. Header и эффект стекла

### Верх страницы

Высота панели — 80 px на desktop, 64 px на mobile. Логотип слева, информационная навигация справа. Панель прозрачна над белой зоной первого экрана; чёрные элементы остаются читаемыми. Декоративная сцена не проходит непосредственно под текстом меню.

### При прокрутке

После 40 px прокрутки панель получает белую полупрозрачную подложку около 90%, размытие 16 px, чёрную рамку 1 px и радиус 12 px. Возврат к прозрачности происходит ниже 16 px, чтобы избежать мерцания около порога.

Плавающий header расположен в 12 px от верхнего края и выровнен по контейнеру. Геометрия и зарезервированное место сохраняются при смене состояния. Допустим тонкий внутренний светлый блик. Сильные искажения текста и имитация оптической линзы не нужны.

При отсутствии поддержки размытия — непрозрачный белый фон с той же рамкой. На внутренних страницах использовать читаемую белую панель сразу. Раскрытое меню всегда непрозрачное.

## 13. Animation principles

- Движение объясняет изменение состояния; пользователь не ждёт окончания анимации, чтобы читать или нажимать.
- Микросостояния: 120–180 ms; раскрытие панели: 220–280 ms; единичное появление композиции: 500–700 ms.
- Для входа подходит плавное замедление, для перемещения интерфейса — симметричный ease-in-out. Пружины и многократные отскоки не являются частью базового характера.
- Анимировать преимущественно прозрачность и трансформации, сохраняя размеры документа.
- Автоматическое декоративное движение заканчивается; бесконечные циклы по умолчанию не используются.
- Не применять мигание, автоматическое воспроизведение звука, движение курсора или захват прокрутки.
- При prefers-reduced-motion показывать сразу конечное статичное состояние, без параллакса и пространственных пролётов.

## 14. Scroll animations

Для нейтральной демонстрации айдентики допустима одна короткая композиция из абстрактных геометрических фрагментов. Логотип сохраняется цельным; его не нужно разбирать на случайные части.

Сценарий: фрагменты уже частично видны → при прохождении секции смещаются на 24–64 px и поворачиваются не более чем на 8° → занимают финальные места. Текст находится вне зоны движения. Анимация привязана к естественной прокрутке, без искусственных нескольких экранов ожидания.

На мобильном смещение сокращается до 12–24 px и исключается закрепление сцены. При reduced motion или ошибке загрузки отображается конечная композиция. Пользователь видит весь контент независимо от выполнения анимации.

Обычные информационные секции не получают обязательный fade-in: они доступны сразу. Навигационные якоря учитывают высоту закреплённого header.

## 15. Изображения и 3D assets

Основной визуальный актив — предоставленная айдентика. Дополнительный объём допустим в нейтральных абстрактных формах: матовая чёрная поверхность, белая керамическая фактура, умеренное жёлтое отражение. Выбрать один материал и один характер света на композицию.

- Предпочтение статичному качественному рендеру, если интерактивная 3D-сцена не даёт отдельной пользы.
- Перспектива спокойная; блики не перекрывают текст; тени мягкие и согласованные.
- Не обрезать оригинальный логотип и не изменять его геометрию ради перспективного эффекта.
- Графика со смыслом получает текстовую альтернативу. Декоративная графика не озвучивается скринридером.
- Для каждого изображения заранее задать пропорции области, чтобы загрузка не сдвигала текст.
- Изображения вне первого экрана подгружаются по мере необходимости; ключевой визуал не скрывается до загрузки всей страницы.
- Рабочие ориентиры веса: до 250 KB для мобильного главного изображения, до 500 KB для desktop; оценивать качество на фактическом размере.
- Файлы пользователя сохраняются без изменений. В public/brand подготовлены уменьшенные WebP-копии без изменения пропорций и PNG favicon. Повторная подготовка: `node scripts/prepare-assets.mjs`. Исходные артефакты не ретушировались.

## 16. Responsive design

Сначала проверяется содержательная иерархия на телефоне. Desktop расширяет композицию, а не добавляет скрытые от мобильных пользователей разделы.

До 768 px: одна основная колонка, компактный header, вертикальный порядок «заголовок → пояснение → визуал → содержание». Информационные карточки по одной в ряд; две допустимы только для коротких вспомогательных элементов.

768–1023 px: до двух карточек в ряд; двухколоночные секции используются только при достаточной длине строк. От 1024 px — полная сетка, до трёх информационных карточек в ряд.

Меню переключается в мобильный режим до возникновения переполнения; начальный ориентир — 1024 px. Широкие таблицы помещаются в собственную область горизонтальной прокрутки с понятным обозначением, не растягивая страницу.

Проверяемые ширины: 320, 375, 390, 768, 1024, 1440, 1920 px. Дополнительно — увеличение текста до 200%, узкое окно desktop, альбомная ориентация телефона и safe-area мобильного устройства. Первый экран не зависит от строго фиксированной высоты viewport.

## 17. Структура витрины и возможных информационных страниц

### Реализованная витрина

Одна страница `/` с якорями:

1. Первый экран: «Характер. В каждой детали.», оригинальный знак и переход к компонентам.
2. `#identity`: логотип, охранное поле, палитра и служебные оттенки.
3. `#typography`: Golos Text, алфавит, цифры, веса и адаптивная шкала.
4. `#components`: кнопки, ссылки, поля, выбор значений, живой предпросмотр, вкладки, карточка, диалог.
5. `#states`: пустой список, ошибка и статичный skeleton. Все данные демонстрационные.
6. `#motion`: контурный круг, чёрная ступенчатая форма, жёлтый квадрат. Движение обратимо; есть статичный режим.
7. Footer: знак, название и возврат наверх.

Header содержит только эти разделы. Поля работают локально, ничего не отправляют и не сохраняют между перезагрузками. Следующие описания информационных страниц сохранены как исходные рекомендации, но отдельные страницы в этот этап не создаются.

### Главная информационная страница

1. **Header.** Знак, ссылки «О проекте», «Материалы», «Контактная информация». Только существующие разделы; никаких пустых пунктов.
2. **Вводная секция.** Название «Прохук», короткое фактическое описание назначения сайта, оригинальный знак. Desktop: текст занимает 5 колонок, визуальная область — 7. Mobile: текст выше визуала. Белый фон; декоративные элементы не превращаются в товарную рекламу.
3. **О проекте.** Краткие проверенные сведения, без выдуманных достижений, чисел и превосходных степеней. Заголовок слева, текст справа; на телефоне — последовательно.
4. **Материалы.** Необязательный блок нейтральных информационных публикаций. Заголовок, краткое пояснение и до трёх карточек. Если материалов нет, секция не выводится.
5. **Контактная информация.** Компактный текстовый блок с подтверждённым общим контактом для обращений. Не подменяет карту точек продажи или путь оформления покупки.
6. **Footer.** Белый фон, чёрная верхняя линия, небольшой логотип, информационные ссылки и дата. Неподтверждённые реквизиты и ссылки не публикуются.

### «О проекте»

Breadcrumbs при необходимости → H1 → вводный абзац → фактическое описание → блок айдентики при наличии содержательной цели → footer. Основной текст ограничен 720 px, графические вставки выравниваются по общему контейнеру.

### Информационный материал

Breadcrumbs → заголовок → дата обновления при необходимости → вводный абзац → изображение с подписью → текст с H2/H3 → источники → ссылка к списку материалов. Содержание длинного документа допустимо сбоку на desktop и в раскрываемом блоке на mobile.

### Контактная информация

H1 → назначение канала связи → подтверждённые общие контакты → служебная информация. Сведения доступны текстом. Формы, виджеты и обработка персональных данных не добавляются автоматически.

### Служебные состояния

404: «Страница не найдена» и ссылка на главную. Ошибка загрузки: конкретное объяснение и «Повторить». Пустой список: спокойное сообщение, без фиктивного содержания. Skeleton повторяет итоговую геометрию и не мерцает. Диалоги имеют видимый заголовок, закрытие и корректное управление фокусом.

## 18. Доступность и критерии приёмки

- На всех страницах фон #FFFFFF; вторичные подложки остаются локальными.
- У жёлтых интерактивных элементов есть чёрный контур и чёрная подпись.
- Основной текст и вторичные подписи читаемы; целевой контраст обычного текста — не ниже 4.5:1, крупного — 3:1.
- Интерактивные границы и индикаторы состояния различимы; цвет не является единственным носителем смысла.
- Все действия доступны с клавиатуры, фокус виден, раскрытое меню не оставляет активными перекрытые элементы.
- Ссылка перехода к основному содержимому доступна с клавиатуры.
- Изменение размеров и загрузка медиа не вызывают заметных скачков страницы.
- Header остаётся читаемым при отключённом blur и не перекрывает заголовки после перехода по якорю.
- При reduced motion весь контент остаётся доступным в статичном состоянии.
- Ни текст, ни функциональность не зависят от hover или декоративной анимации.
- Результаты проверки реализации фиксируются в docs/QA.md; наличие правила в этом документе не заменяет фактическую проверку.

## 19. Подтверждённые решения и ограничения

- Результат — Nuxt-витрина, базовые компоненты и обновлённый документ.
- Header использует `2.png`, полный логотип — `3.png`. Ступенчатая форма из «основной логотип.png» не подменяет знак.
- Утверждены Golos Text, строгая светлая композиция и одна нейтральная scroll-анимация.
- Сохранены радиусы и токены этого документа; язык витрины — русский.
- Векторный логотип и официальный брендбук не предоставлены. Охранные поля остаются рабочими правилами, не официальной спецификацией.
- У внешних референсов проверено текстовое содержание; точные анимации и мобильные композиции визуально не подтверждены. Они не копируются.
- Контакты, адреса, товарные фотографии и доступ к МойСклад не нужны для согласованного этапа.
- Публикация на хостинге не входит в этап.

## 20. Реализация и проверка

Техническая основа: Nuxt 4, Vue 3, TypeScript, собственные Vue-компоненты и CSS. Токены находятся в `app/assets/css/main.css`, витрина — в `app/app.vue`, компоненты — в `app/components`. Зависимости зафиксированы lock-файлом. TypeScript ограничен веткой 5.9 для совместимости с установленным vue-tsc.

- UiButton: primary / secondary / quiet, два размера, disabled и loading без изменения ширины.
- UiField и UiSelect: управляемая модель, подписи, подсказки и ошибки с ARIA-связями, SSR-стабильные ID.
- UiTabs: стрелки, Home/End, roving tabindex и связанные tabpanel.
- UiDialog: нативный modal dialog, блокировка фона и прокрутки, Tab/Shift+Tab внутри, Escape и возврат фокуса. Используется также мобильным меню.
- UiCard: изображение, ссылка в заголовке и описание, без скрытых действий.
- MotionStudy: requestAnimationFrame только для видимой сцены, статичное состояние без JavaScript и при reduced motion.

Запуск: `npm ci`, затем `npm run dev`. Проверки: `npm run typecheck`, `npm run build`, `npm test`. Перед первым запуском тестов: `npx playwright install chromium webkit`.

Интерфейсы компонентов и инструкции — в README.md. Скриншоты — в docs/screenshots, фактические результаты проверок — в docs/QA.md.
