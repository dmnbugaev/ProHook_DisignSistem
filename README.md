# PROHOOK — каталог товаров с МойСклад

Локальный проект на Nuxt 4, Vue 3 и TypeScript. Категории, товары, фотографии, цены и остатки загружаются сервером из МойСклад. Клиент не получает ключ API.

## Запуск

Node.js 22+; проверено на Node.js 24.21.0.

```sh
npm ci
cp .env.example .env
# Укажите NUXT_MOYSKLAD_TOKEN в .env
npm run catalog:sync
npm run dev
```

Открыть http://127.0.0.1:3000. Сервер слушает localhost. Публикация не настроена; страницы имеют `noindex, nofollow`.

```sh
npm run build
npm run preview
```

Production: `node .output/server/index.mjs`, Nitro node-server. На сервере требуется `NUXT_MOYSKLAD_TOKEN`; `.env` и `.cache` не добавляются в Git. При первом запуске без снимка каталог загружается из МойСклад, а остатки догружаются в фоне. Для предсказуемого первого открытия заранее выполните `npm run catalog:sync`.

## Страницы

| Адрес | Содержание |
| --- | --- |
| `/` | Главная: hero, категории, подборка, бренды, о проекте, магазины и контакты |
| `/catalog` | Фильтры, сортировка, количество результатов, карточки и пагинация |
| `/catalog/[category]` | Категория или подкатегория; родитель включает товары дочерних категорий |
| `/product/[slug]` | Галерея, характеристики, описание, цены и наличие по точкам, похожие товары |
| `/search?q=` | Поиск по названию, бренду и артикулу |
| `/register`, `/login` | Регистрация и вход по номеру телефона и паролю |
| `/account` | Личный кабинет: бонусы Тейка, личные данные, выход |
| `/reserve` | Список выбранных товаров и запрос на резерв для самовывоза |
| `/about`, `/contacts`, `/stores` | Информационные страницы |
| `/information` | Об источнике каталога и хранении выбора магазина |
| `/design-system` | Исходная интерактивная витрина дизайн-системы |

AgeGate запрашивает 18+ при каждой загрузке документа. При переходах внутри Nuxt ответ сохраняется в памяти; после reload спрашивается снова. Без JavaScript интерфейс заблокирован и показано пояснение. После подтверждения предлагается выбрать город и магазин. Выбор точки хранится в cookie `prohook-store` на 30 дней и доступен при SSR. Страницы аккаунта (`/login`, `/register`, `/account`) открыты без AgeGate: возраст подтверждается датой рождения в аккаунте, а не декларацией.

Возрастной контроль изображений устроен в два уровня. Cookie гейта — только декларация для просмотра каталога; изображения товаров видны исключительно пользователям с подтверждённой датой рождения 18+ в аккаунте. Сервер отдаёт `images: []` с флагом `imagesRestricted` из `/api/products*` и `/api/catalog/meta`, а сам прокси `/api/products/:id/images/:index` без взрослой сессии отвечает 403 — прямой URL открыть нельзя, обход через DevTools ничего не даёт. Анонимы и несовершеннолетние видят нейтральную заглушку «18+».

Список выбранных товаров и запрос на резерв: пользователь собирает товары кнопкой «В список» (cookie `prohook-selection`, 30 дней), выбирает магазин и отправляет запрос `POST /api/reservations` (имя, телефон, комментарий, два согласия, SmartCaptcha). Запрос сохраняется в `.data/reservations` и рассылается ботом `@prohook_bunker_site_bot` (env `TELEGRAM_BOT_TOKEN` + `TELEGRAM_RESERVATION_CHAT_IDS`) ответственным сотрудникам. Это не интернет-магазин: оплаты и доставки на сайте нет, продажа — только в магазине после проверки возраста; сервер перепроверяет магазин, товары и остатки по снимку МойСклад и не доверяет данным клиента.

## Данные и API

- `GET /api/catalog/meta`: категории, бренды, города, магазины и материалы.
- `GET /api/products`: `{ items, total, page, pageCount }`.
- `GET /api/products/:slug`: `Product` или HTTP 404.
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`: аккаунты (см. ниже).
- `GET /api/account/loyalty`: бонусы Тейка для вошедшего пользователя.

Query: `q`, `category`, `minPrice`, `maxPrice`, `available=1`, `storeId`, `sort`, `page`, `limit`. Внутренние подборки дополнительно используют `excludeId`.

Сортировки: `popular` (по дате последнего обновления для совместимости URL), `price-asc`, `price-desc`, `newest`. Фильтры и страницы синхронизированы с URL. Неизвестная категория/товар возвращает 404; некорректный диапазон цены или неизвестная точка — 400. Размер выдачи ограничен 24, страница приводится к существующему диапазону.

У `Product` есть массив `offers`: `storeId`, `price`, `currency`, `availability`. Денежные значения — целое количество копеек. Наличие — `available | low | unavailable | unknown`, без публикации количества. Фильтры цены в URL задаются в рублях. Для Саратова используется тип «Цена продажи», для Москвы — «Москва». Нулевая цена скрывает товар в соответствующем городе. Без выбранного магазина показывается минимальная положительная цена с подписью «от».

Данные поступают из МойСклад и сохраняются в `.cache/moysklad/catalog.json`. В каталог попадают неархивные обычные товары с положительной ценой хотя бы в одном городе. Если в МойСклад появится дополнительное поле «Показать на сайте», публикуются только отмеченные товары; сейчас такого поля нет. Модификации не включаются. Из 43 складов показываются 30 неархивных торговых точек групп «Саратов» и «Москва»; служебные склады исключаются. Ручной запрет для «Вокзала», «Буровой», «Ильинской площади» и «Чапаева 45» снят. Остатки связываются по ID склада из `meta.href`; сопоставление по уникальному имени используется только для ответов без ID.

Для полных названий на витрине создайте в МойСклад дополнительное текстовое поле товара **«Название для сайта»** и заполните его у нужных товаров. Синхронизация использует это поле для карточек, страницы товара, поиска и подписей изображений. Если поле пустое, остаётся исходное название из МойСклад. Учётное название, документы и печатные формы при этом не меняются. После заполнения выполните `npm run catalog:sync` или дождитесь фонового обновления каталога (до пяти минут).

## Синхронизация

`npm run catalog:sync` загружает полный каталог и отчёт остатков перед запуском. Сервер читает снимок сразу и обновляет товары и остатки в фоне через пять минут. При временной ошибке МойСклад остаётся последний успешный снимок; если остатков ещё нет, выводится «Наличие уточняется».

Изображения открываются через серверный `/api/products/:id/images/:index`, поэтому ссылки скачивания и ключ МойСклад не попадают в браузер. Если изображения нет, интерфейс показывает существующую заглушку.

## UI Kit

Сохранены `UiButton`, `UiField`, `UiSelect`, `UiTabs`, `UiDialog`, `UiCard`. Выделены `UiContainer`, `UiIconButton`, `UiCheckbox`, `UiEmptyState`, `UiSkeleton`; добавлены `UiBadge`, `UiBreadcrumbs`.

Варианты кнопок остаются `primary / secondary / quiet`, размеры `normal / large`. `UiDialog` поддерживает модальную панель, `drawer` и обязательное подтверждение через `dismissible=false`. Диалоги удерживают фокус, обычные закрываются по Escape. `UiContainer` поддерживает семантический тег через `as`.

## Отложенные данные

## Юридическое соответствие

Полный аудит, карта товаров, Data Flow Map и обязанности владельца — в `docs/COMPLIANCE.md`. Ключевое:

- Справочный каталог: корзины, заказа, оплаты и доставки нет ни в UI, ни в API; продажа — только в магазинах после проверки возраста.
- Юридическая классификация ассортимента применяется централизованно (`shared/legal/classification.ts`): запрещённые и неклассифицированные категории не публикуются; для регулируемых не публикуются свободные описания; новые корневые категории МойСклад по умолчанию скрыты до классификации.
- Региональные запреты (ЭСДН и жидкости в Саратовской области с 01.03.2027) включаются автоматически по дате (`shared/legal/regional-restrictions.ts`).
- Возрастной гейт 18+: подтверждение хранится в cookie `prohook-age-confirmed` (1 год); до подтверждения контент каталога не рендерится даже в SSR-HTML. Юридические страницы открыты без гейта.
- Форма партнёрства требует два раздельных согласия (обработка ПД; передача через Telegram), оба пустые по умолчанию.
- МРЦ: проверка-предупреждение при `npm run catalog:sync` (`shared/legal/min-prices.ts`); пороги заполняет владелец после сверки с действующей редакцией постановления; цены автоматически не меняются.
- Лицензии 186-ФЗ: модель данных готова (`server/data/store-licenses.ts`), реквизиты выводятся только после заполнения владельцем.
- Security-заголовки (CSP, X-Frame-Options и др.) — в `nuxt.config.ts`; robots.txt запрещает индексацию до решения о публикации.

## Личный кабинет и бонусы Тейка

Регистрация: ФИО, дата рождения, телефон и пароль (Argon2id, `@node-rs/argon2`).
Телефон нормализуется в `7XXXXXXXXXX` и уникален; подтверждение пароля и
согласие на обработку ПД проверяются на сервере. Вход — телефон и пароль с
единым сообщением об ошибке («Неверный телефон или пароль») без раскрытия,
какое поле неверно; на несуществующий номер выполняется фиктивная проверка
хеша для выравнивания времени ответа.

Сессия — случайный 256-битный токен в HttpOnly-cookie `prohook-session`
(SameSite=Lax, Secure в production, TTL 30 дней). В хранилище лежит только
SHA-256 токена, logout инвалидирует запись на сервере. Аккаунты и сессии
хранятся в JSON-файлах `ACCOUNT_DATA_DIR` (по умолчанию `.data/account`,
вне Git) с атомарной записью — БД в проекте нет, это тот же паттерн, что и
снимок каталога. Rate limit в памяти процесса: регистрация 5/15 мин на IP,
вход 10/15 мин на IP и на телефон (пороги — `AUTH_RATE_LIMIT_*` только для
тестов). Для нескольких реплик нужна общая БД и лимитер на прокси.

Возраст: `isAdult()` из `shared/utils/account.ts` сравнивает точные даты
(05.10.2008 → 18 при сегодня 05.10.2026; 06.10.2008 → ещё 17). Совершеннолетие
с аккаунта — единственный источник для `canViewProductImages`; cookie гейта
считается только декларацией для просмотра каталога.

Тейка (`server/services/teyca.ts`): официальный API `https://api.teyca.ru`.
Основной ключ `TEYCA_API_KEY` передаётся в заголовке `Authorization` и живёт
только на сервере. Токен экземпляра берётся из `TEYCA_API_TOKEN` либо
создаётся автоматически (`/v1/authorization` с идентификатором
`TEYCA_IDENTIFIER`) и сохраняется в `ACCOUNT_DATA_DIR`. Поиск клиента —
`GET /v1/{token}/passes?search=phone=…`, баланс — `GET /v1/{token}/passes/userid/…`
(поле `bonus` приходит строкой). Клиент в Тейка автоматически не создаётся:
карта выдаётся в магазине, сайт лишь привязывает её по телефону при
регистрации или первом открытии «Моих бонусов». Тейка — единственный источник
баланса; при недоступности API блок показывает «Не удалось загрузить
информацию о бонусах», а в server-лог пишется причина без ключей и телефонов.

Ключ Тейка — секрет: он не попадает в клиентский бандл, DOM, логи и ответы
API. Все запросы выполняются только из Nitro-обработчиков.

## Партнёрские заявки и Telegram

Страница `/partners` доступна из меню, подвала и блока контактов главной страницы.
Форма отправляет JSON на `POST /api/partnership`. Поля: `name`, `phone`, `city`,
`company`, `offer` (текст предложения, 10–500 символов), `consent: true`
(согласие на обработку ПД), `consentTelegram: true` (согласие на трансграничную
передачу через Telegram). Сервер проверяет данные и отправляет сообщение в
указанный чат от имени бота. Токен и ID чата находятся только в приватном
runtime config.

### Подключение

1. Создайте бота через [@BotFather](https://t.me/BotFather), командой `/newbot`.
2. Откройте созданного бота и нажмите «Начать». Для групповых заявок добавьте
   бота в закрытую группу команды и отправьте в ней команду `/start@имя_бота`.
3. Получите `message.chat.id` через Telegram Bot API `getUpdates` в своей
   доверенной среде. Для группы ID обычно отрицательный. Не публикуйте токен
   и не передавайте его сторонним сервисам получения chat ID.
4. Заполните локальный `.env` либо переменные окружения хостинга:

   ```dotenv
   NUXT_TELEGRAM_BOT_TOKEN=токен_из_BotFather
   NUXT_TELEGRAM_CHAT_ID=id_личного_чата_или_группы
   ```

5. Перезапустите сервер. Для production: `npm run build`, затем
   `node .output/server/index.mjs` с указанными переменными окружения.
   Production-сервер не читает `.env` автоматически. Нужен сервер Nuxt/Nitro,
   статический хостинг не выполняет API.
6. Отправьте тестовую заявку с `/partners` и проверьте получение сообщения.

Используется [Telegram Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage).
Webhook и отдельный процесс бота не нужны: бот доставляет заявки команде,
обработка диалогов с посетителями в эту интеграцию не входит.

### Поведение и ограничения

- Успех показывается только после ответа Telegram `ok: true` с `message_id`.
- Без настроек возвращается 503, при ошибке Telegram — 502; форма сохраняет
  введённые данные. Автоматических повторов нет, чтобы не создавать дубли.
  При сетевом таймауте доставка может уже состояться — проверьте чат перед повтором.
- Проверка на сервере, лимит тела 8 КБ, поле-ловушка и ограничение
  5 попыток за 15 минут на IP. Чужие `X-Forwarded-For` не используются.
  Лимит хранится в памяти процесса и сбрасывается при рестарте. Для нескольких
  экземпляров и работы за reverse proxy настройте общий rate limit на прокси
  по проверенному адресу клиента; иначе клиенты прокси делят один лимит.
- Заявки не сохраняются в базе; полученные сообщения остаются в чате Telegram.
  Токены и содержимое заявок не записываются в логи обработчика.
- Проверки: `npm run test:unit` и
  `npx playwright test tests/partnership.spec.ts`. Тесты используют подмену
  Telegram и не отправляют реальные сообщения.
